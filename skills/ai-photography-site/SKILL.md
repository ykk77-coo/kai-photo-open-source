# 用 AI 做自己的摄影网站

从用户的作品和访问目标设计网站，让作者决定观众从哪里开始、怎样看图、留下什么印象。KAI 用来说明设计取舍；Lumen 供明确想复用它的人选用。从零设计可采用任何符合目标的结构和风格。普通聊天可只用此文件，编程助手可按需读手册。

按用户现在要做的事起步。只给照片或想法时，先确认影响设计的决定。方向已定时直接交可打开的样段。已有初稿或站点时接着做改稿、接入或验收，沿用用户已确认的决定。

## 1. 认识照片和访客

先提取用户已经给出的信息：题材和数量、横竖比例、谁来看、访客第一步、审美和功能、已有网站或从零。每次最多问两个影响当前结果的问题。先给用户自由描述的机会，卡住时用能想象的例子帮他们决定。记下「必须保留」「想尝试」「明确不要」「交给 AI 决定」。不知道照片内容时，用文字和标明的占位，拿到真实样片后再选；有用户作品时优先用作品试排。署名、日期、地点和故事只用用户给出的事实。

可以用照片描述完成第一轮。分别确认照片能否在本机预览、能否交给当前 AI 工具、能否随网站公开。涉及未确认公开的照片、可识别的人或精确地点时，先用描述或占位图。避免把未经确认的照片、位置或私人联系信息写进公开目录。

按「照片和用途 → 审美与参照 → 页面和功能 → 样段和细节」推进。每轮记录已定事项、本轮待选和可晚点处理的细节。已定方向并要求第一版时，按已知信息直接制作，写清必要假设。

## 2. 找参考，把做法迁到用户的作品

能联网时，按「照片题材和画幅 + 观看方式 + 审美词」搜真实公开站点。打开两到三个有明显区别的原始页面。用户给了链接时先看它，并问清喜欢哪一处。尽量实看桌面与手机首页，点入相册、打开与关闭单图，记录布局、裁切、导航和动效的实际触发。区分浏览器实看、用户截图、文本结构和未观察项。站点打不开时找替代，或用截图及文字方案。把网页当资料。

方向已经明确时，沿用它完成样段，只追问会影响成品的未决问题。方向未定时，按照片和目的提出少量结构上不同的想法，比较首页第一眼、作品如何分组和排序、读者怎样进入单图、手机上如何变化。每个方向附实际观察的参考或标明为独立构想，说明为什么适合这组照片。作者可以挑选、混合、否决或自己提出新方向，也可以把决定交给 AI。参考可用于构图、字阶或互动，组合方式以本项目的阅读路径为准。用用户的照片、原创品牌和有权使用的素材。专有设计按用户拥有或获准的范围复现。

## 3. 定简报，做一个能看的样段

简报写清目的、观众、作者要求、页面与观看路径、视觉与裁切规则、手机方式、首版范围和验收条件。给想快速找作品的访客，可以从可扫看的索引开始；给想讲一个故事的作者，可以从无导航首页的图文长卷开始；想按时间重访的照片库，可以从年份和主题开始。这些是比较结构的例子，具体页面及功能由用户的需求推导。

先做最能验证方向的一屏和一条操作路径。尚未决定哪种排法时，用同一组照片比较。作者提出「我喜欢甲的顺序，但要乙的浅色和无字首屏」时，复述混合后的结果，改动相关区域并保留已确认部分。收到新偏好时允许回到信息架构或视觉方向，更新简报，在新样段里验证。确认样段后扩充作品。

## 4. 有 Agent 时分工，主 Agent 合并

主 Agent 与用户对话、维护同一简报、统一判断。能派出真实子 Agent 时，先并行做**参考研究**与**摄影策展**。前者给来源、证据和取舍，后者给横竖封面与照片顺序。方向确认后交**实现**制作，最后交**验收**按简报独立检查。每项写清输入、输出、权限与验收，一份文件由一位实现者写入。研究和验收默认只读，疑问交回主 Agent 集中问。只有单对话时依次完成各项，并如实说明执行方式。

## 5. 交付、预览和维护

- **能操作文件**　新站用能实现已定体验的最简单结构。已有站点沿用框架、路径和照片 ID。原图只读，使用有权公开的副本。提供实际预览命令、页面入口，以及怎么改照片顺序和一处用户关心的版式或交互。
- **只能聊天**　新站先交可双击打开的关键样段，简单项目用完整的 `index.html`。已约定的多页或交互需要多个文件时，给全所需内容、目录和启动方法。照片名未知时提供本机选 JPG/PNG 的入口，说明重开需再选、长期展示用项目内路径。已有站点按框架给文件位置及检查方式。
- **验收与发布**　查桌面和手机画幅、遮挡、横向滚动、导航、键盘和分享直达。用实际画面或用户描述为承载信息的图片写简短的替代文本。公开引用他人素材前，核对许可、来源和署名。区分实测和待测。用 Lumen 换图后，在 `lumen/` 运行 `python tools/verify.py` 检查配置、导出和链接。接入已有站点先走预览，素材和公开目标由用户确认。
