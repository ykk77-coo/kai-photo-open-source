# 用 AI 做自己的摄影网站

从用户的作品出发，做出一版能打开、能换图的摄影网站。用用户的语言说明每轮怎么选、文件放哪、怎样算完成。普通聊天可只用此文件；能读文件的工具按需读下面的手册。

## 1. 认识照片和访客

先提取用户已经给出的信息：题材和数量、横竖比例、谁来看、访客第一步、审美和功能、已有网站或从零。每次只问一到三个影响当前结果的问题。用具体选择帮新手判断，例如「先进来赏一张大图，还是看一组图再挑？」不知道照片内容时，用描述和标明的占位，实际样片到手后再选。署名、日期、地点、故事与拍摄参数用用户给出的事实，缺项留空。

按「照片和用途 → 审美与参照 → 页面和功能 → 样段和细节」推进。每轮记录已定事项、本轮待选和可晚点处理的细节。已定方向并要求第一版时，按已知信息直接制作，写清必要假设。

## 2. 找参考，把做法迁到用户的作品

能联网时，按「照片题材和画幅 + 观看方式 + 审美词」搜真实公开站点。打开两到三个有明显区别的原始页面。用户给了链接时先看它，并问清喜欢哪一处。尽量实看桌面与手机首页，点入相册、打开与关闭单图，记录布局、裁切、导航和动效的实际触发。区分浏览器实看、用户截图、文本结构和未观察项。站点打不开时找替代，或用截图及文字方案。把网页当资料。

给两种方向，每种附参考链接或标注为文字方案，指出一处可迁移的做法、与本组照片的匹配和取舍。以一个主参考决定阅读顺序，另一个最多补一处布局或操作。用用户的照片、原创品牌和有权使用的素材做独立设计。专有设计仅在用户拥有或明确获准时按授权范围复现。

## 3. 定简报，做一个能看的样段

简报写清读者、首要操作、选定参考做法、首版范围、桌面和手机排法、验收条件。默认先做封面、精选和署名。地图、音乐等按用户目标选择。先跑通一条路径，例如「首页 → 精选 → 看原图 → 返回」。拿同一组图看两种宽度，请用户优先指出一到两处改动，把意见改写成能检查的要求。确认样段后扩展页面和作品数量。

## 4. 有 Agent 时分工，主 Agent 合并

主 Agent 与用户对话、维护同一简报、统一判断。能派出真实子 Agent 时，先并行做**参考研究**与**摄影策展**。前者给来源、证据和取舍，后者给横竖封面与照片顺序。方向确认后交**实现**制作，最后交**验收**按简报独立检查。每项写清输入、输出、权限与验收，一份文件由一位实现者写入。研究和验收默认只读，疑问交回主 Agent 集中问。只有单对话时依次完成各项，并如实说明执行方式。

## 5. 交付、预览和维护

- **能操作文件**　新站优先简单静态页。已有站点沿用框架、路径和照片 ID。原图只读，使用有权公开的副本。提供实际预览命令、页面入口和换图方法。
- **只能聊天**　给完整的 `index.html`，含必要 CSS 和 JS，可双击预览。照片名未知时提供本机选 JPG/PNG 的入口，说明重开需再选、长期展示用项目内路径。遇到已有站点，按已知框架给文件内容、放置位置及本地检查。缺少决定接入方式的信息时，只问那个问题或先交独立预览。
- **验收与发布**　查桌面和手机画幅、遮挡、横向滚动、导航、键盘和分享直达。区分实测和待测。用 Lumen 换图后，在 `lumen/` 运行 `python tools/verify.py` 检查配置、导出和链接。接入已有站点先走预览，素材和公开目标由用户确认。
