# 多 Agent 分工与交付

多人协作的价值是分别对参考、照片和作品体验提供证据。先确认当前工具能启动真正的子 Agent、能用哪些文件和浏览能力。仅有普通对话时，使用本文件的角色顺序逐项自查；如果用户另开对话，可使用交接卡分配独立任务。

## 按依赖安排角色

| 角色 | 何时开始 | 具体输入和产出 |
| --- | --- | --- |
| 主 Agent | 从第一轮开始 | 维护一份简报，决定本轮问题、过滤候选、确认样段、归并修改和验收 |
| 参考研究 | 知道用途、照片条件和审美后 | 读简报与勘察手册。返回两三个官方页面、证据类型、可迁移点和取舍 |
| 摄影策展 | 同一轮可与参考研究并行 | 使用者允许查看的样片、尺寸或描述。返回两组样片顺序、桌面与手机的封面选择、事实待补项 |
| 实现 | 方向已确认后 | 已确认简报、可用素材、目标目录、接口与范围。先交付关键样段，再扩展页面 |
| 验收 | 有可访问样段或完整版本后 | 同一阶段的简报、版本或地址、验收清单。返回可复现步骤、预期、结果与尚未覆盖细节 |

小项目由主 Agent 兼做实现即可。有多条独立工作时再分派。参考研究和摄影策展默认只读。每个文件或组件指定一个写入者。不同人做同一页面的备选稿时，分在各自目录或分支，由主 Agent 比较并选一个合入。实现完成后再做独立验收。

## 可复制的 Agent 交接卡

~~~text
项目快照：已有网站或从零，读者是谁，主要观看路线。
已确认：照片题材和状态，选定参考、布局、功能，本阶段目标。
你的角色与任务：本轮只需要哪一项输出。
可用输入：允许查看的网页、样片、文件或简报。
写入范围：只读／明确的目录和文件；分配的页面由一位实现者负责。
返回格式：已观察证据、产物位置、检查结果、待主 Agent 判断的事项。
完成标准：相关路径、图片、桌面和手机要到什么状态。
~~~

分工不构成新的发布授权。使用者确认的相册、照片和身份信息仅按原范围交给需要它的角色。研究、策展和评审通过主 Agent 提问。

## 主 Agent 如何合并结果

1. 并行收回研究和策展输出。逐条确认参考看得见的事实。遇到宽横幅参考与竖图较多的矛盾，优先让内容被正确看到，向使用者提出「另选竖幅」和「保留横幅、手机用适配版」两种可见选择。
2. 将选定方案写成可实现任务，明确页面、素材键、交互、桌面和手机验证。实现者报告改变的文件、入口、依赖与自测，自己有疑问时反馈阻塞点。
3. 验收者按简报走路径，把严重的路径中断、不可用控件、照片失真和公开数据范围问题先交回实现修复，再讨论美术偏好。反馈附视口、动作和结果。主 Agent 对照实际产物确认修复。
4. 向使用者只呈现本轮产物、需要其判断的选项和下一步。说明哪些角色是真正执行的子 Agent，哪些是单对话角色切换。

## 第一次制作与完成标准

- **先做样段。** 一组样片、一个封面加首排作品、一个主要操作，能在电脑和手机上打开。完整图以原比例展示，网格缩略图的裁切按用户确认的范围。
- **扩成首版。** 按已定路径添加页面和照片。有看图器时验证键盘、关闭、返回原列表和分享。图片路径与替换第一张图的方法可说清楚。原图只读，并在公开前核对自行添加的文字、署名及位置等信息。
- **按能力交付。** 能操作文件时，列出入口或预览命令，实际运行验证。只有聊天时，先交一份可打开的独立文件或现有框架中清楚可保存的文件。把操作清单交给用户，并根据其截图迭代。
- **确认后接入。** 现有站点先走预览环境，核对路径、导航和资源。发布范围和目标经用户确认后，再执行可用的公开发布步骤。
