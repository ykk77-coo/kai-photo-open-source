# 架构与数据流

## 静态入口

六个 HTML 入口共用脚本与样式，根据路径决定首页、作品库、旅程目录、系列、地图或介绍页。支持 `.html` 及托管服务提供的简洁地址；普通本地服务器使用 HTML 地址。

加载顺序是：站点配置 → 照片目录 → 渲染函数定义 → 页面运行时 → 地图/导航和外观增强 → 看图器 → 书签与随机看图。没有远程数据库或登录服务。

## 内容配置

- `window.PHOTO_SITE` 是品牌、作者、四个首页分类、旅程、专题与介绍配置。
- `window.KAI_PHOTOS` 是可浏览的作品清单。保留既有作者键与查询参数规则，方便稳定链接。
- `window.KAI_PROVINCE_MAP` 包含离线 SVG、区域名称及代码、来源说明和是否示意图的标记；边界转换仅读取用户自备的本地数据。

`v2.js` 提供共享内容访问与页面路由；`photography.js`、`gallery.js`、`essays.js`、`atlas.js` 分别负责旅程与参数、筛选、专题和地区浏览。桌面和手机都从「更多浏览」进入同一个目录。代码按职责拆分，部分旧模块包含较长的样式和模板字符串。理解版式时可以先读[图文案例](制作方法.md)。

## 统一看图器

照片卡片进入当前作者的全部作品集合；列表筛选和专题阅读顺序不改变全库循环规则。看图器统一处理参数、显隐、加载失败、链接与键盘操作，手势模块负责缩放及拖动，避免缩放时误触翻页。

查看事件供书签模块记录成功加载的照片；本地存储不可用时，看图继续可用。随机模块仅在会话内维护当前作者抽取顺序，普通左右翻页仍按作品库顺序。

## 本地工具与部署

导入工具默认追加、生成网页副本，并保留选定的 EXIF 字段和稳定 ID。配置检查验证 ID、封面、专题归属和本地依赖。构建工具按白名单复制公开站点资源，并生成可直接阅读的首屏和图文。提供实际 HTTPS 地址时，还生成单图页、分享元数据和站点地图。仓库里的手册和交互小样通过源码预览入口打开。

换过内容时可运行 `python tools/verify.py` 检查自己的配置、导出和链接。`npm test` 回归默认示例的已知路线。Python 集成测试用临时图像和测试 EXIF 验证导入、地区数据、预览与静态导出。Node.js/happy-dom 用于测试，线上使用静态文件。

## 可选增强
features.js负责从配置提供手记/推荐并收整可选入口，viewer-experience.js提供画框和手记，further.js处理章节末尾推荐。atlas.js使用手机选择、可控拖动与恢复状态。静态构建按显式白名单复制这些运行文件，不复制AI协作文档、private或工具。
